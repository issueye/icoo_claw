# Codex 风格桌面 AI 对话客户端需求文档

- 文档版本：V0.1
- 创建日期：2026-05-19
- 适用范围：`icoo_claw` 桌面客户端
- 目标技术栈：Go、Wails3、TOML、JavaScript、Vite、Vue3、Pinia、Vue Router、Tailwind CSS
- 文档状态：初稿，基于当前仓库能力和截图做默认假设

## 1. 项目背景

当前仓库已经具备 `gateway`、`claw`、`session_store` 三个后端服务，核心聊天链路已围绕会话、消息、流式输出和 agent 实例管理展开。下一步需要补齐一个桌面端产品，用于复刻 Codex App 的主要交互形态，让用户可以直接在本地桌面完成会话管理、消息发送、流式阅读、项目切换、配置管理和网关接入。

本项目不是再做一个通用网页聊天页，而是实现一个以“桌面 AI 工作台”为目标的客户端。界面风格、导航结构和基础交互参考 Codex App，但底层能力要对接本仓库现有网关，而不是直接耦合第三方 API。客户端需要优先保证聊天主链路稳定，再逐步扩展技能、插件、自动化、搜索等工作台能力。

## 2. 产品目标

### 2.1 总体目标

构建一个 Windows 优先、可扩展到 macOS/Linux 的桌面 AI 聊天程序，具备以下特征：

- 具备 Codex 风格的左侧导航、会话列表、中间聊天区和底部输入区。
- 通过网关统一访问会话、消息、流式响应和 agent 能力。
- 使用 TOML 持久化桌面端配置，支持本地修改与启动加载。
- 前后端边界清晰：Wails3 Go 层负责系统能力和配置桥接，Vue3 前端负责 UI 与交互。
- 保留后续接入搜索、技能、插件、自动化等工作台模块的扩展点。

### 2.2 成功标准

- 用户可以完成“配置网关 -> 创建会话 -> 发送消息 -> 查看流式响应 -> 查看历史会话 -> 切换会话”的完整闭环。
- 应用重启后可恢复上次配置、最近项目、最近会话列表和 UI 偏好。
- 当网关异常、会话忙碌或流式中断时，界面能明确提示，不出现卡死、白屏或无反馈状态。

## 3. 产品定位与范围

### 3.1 产品定位

这是一个单用户桌面 AI 工作台客户端，首版优先面向开发者或内部使用者，核心诉求是稳定、清晰、接近 Codex App 的交互体验。

### 3.2 本期范围

本期优先交付：

- Wails3 技术可行性验证与桌面工程基线。
- 桌面应用壳。
- 聊天主界面。
- 会话管理。
- 网关配置与连通性检测。
- 流式对话。
- 基础项目切换。
- 本地配置管理。
- 搜索、技能、插件、自动化模块的页面占位与导航骨架。

### 3.3 暂不纳入本期

- 多用户登录与权限系统。
- 云端配置同步。
- 复杂文件上传解析。
- 真正意义上的全文搜索引擎。
- 自动化任务执行引擎。
- 插件安装市场。
- 与移动端同步。

## 4. 默认业务假设

为保证首版能快速落地，当前文档采用以下假设：

- 首版以单机本地使用为主，不做账号体系。
- 首版仅支持网关模式，不提供本地模式切换。
- 网关由用户或开发环境单独启动，桌面端通过 HTTP + WebSocket 接入。
- 桌面端与网关的实时对话链路首版改为 WebSocket，不再以 SSE 作为桌面客户端主协议。
- 聊天主链路复用现有 `gateway` 的 conversation API。
- “技能 / 插件 / 自动化 / 搜索” 首版以结构和入口占位为主，能力深度按网关实际 API 逐步补齐。
- 配置文件采用 TOML，默认保存在用户目录下的应用配置路径。
- 首版优先支持 Windows，界面和交互要兼容 Wails3 桌面窗口模型。

## 5. 用户角色

当前只定义一种核心角色：

- 本地操作用户：使用桌面客户端配置网关、管理项目、发起对话、查看历史、切换 agent 和调整设置。

后续可扩展角色，但不进入本期设计。

## 6. 核心使用流程

### 6.1 首次启动

1. 用户打开应用。
2. 应用检测本地 TOML 配置是否存在。
3. 若不存在，进入首次引导或设置页，要求填写网关地址、默认模型、默认工作目录等。
4. 用户保存配置后，应用执行网关连通性检测。
5. 检测成功后进入主界面。

### 6.2 新建会话

1. 用户在左侧点击“新对话”或进入欢迎页直接输入问题。
2. 应用先检查当前是否选择了默认 agent / 模型 / 项目。
3. 前端调用网关创建会话接口。
4. 创建成功后进入会话详情页。
5. 用户发送首条消息，应用展示流式响应。

### 6.3 持续对话

1. 用户在当前会话中继续输入。
2. 应用调用流式消息接口。
3. 前端实时渲染增量内容、状态和错误信息。
4. 会话结束后自动刷新会话列表和更新时间。

### 6.4 历史恢复

1. 用户从左侧会话列表点击历史会话。
2. 应用加载该会话消息记录。
3. 中间区域恢复会话内容和发送状态。

## 7. 功能需求

### 7.1 应用壳与窗口

- 使用 Wails3 构建桌面应用。
- 支持自定义标题栏或接近截图风格的顶部工具区。
- 支持窗口最小化、最大化、关闭。
- 支持应用菜单：文件、编辑、视图、窗口、帮助。
- 支持窗口尺寸记忆与上次位置恢复。
- 支持深色/浅色主题切换，首版默认浅色。

### 7.2 左侧导航

左侧导航需要保留 Codex 风格的信息架构，至少包含：

- 快速对话
- 搜索
- 技能
- 插件
- 自动化
- 项目列表
- 对话列表
- 设置

要求：

- 一级导航可点击切换主视图。
- 项目列表与对话列表分区展示。
- 支持当前项高亮。
- 支持空状态、加载状态和错误状态。
- 除聊天主链路外，其他导航首版允许进入占位页，明确标记“即将支持”或展示静态结构。

### 7.3 聊天主界面

聊天主界面为首版核心模块，包含：

- 欢迎态空白页。
- 会话消息列表。
- 用户消息气泡。
- AI 响应消息块。
- 流式生成中的增量渲染。
- 发送中、完成、失败、中断等状态提示。
- 输入框、发送按钮、模型选择、权限模式、项目上下文显示。

交互要求：

- 支持回车发送、`Shift + Enter` 换行。
- 发送后立即插入用户消息占位，避免界面停顿。
- 流式输出过程中自动滚动到底部，但用户手动上滑后不强制抢焦点。
- 失败时可显示重试入口。

### 7.4 输入区

输入区参考截图结构，至少包含：

- 多行文本输入框。
- 发送按钮。
- 当前连接网关/模型的下拉选择器。
- 当前权限模式显示。
- 当前项目或工作目录显示。

预留但不强制首版完成：

- `@` 技能提及。
- 文件选择与上下文附加。
- 对话参数快捷切换。

### 7.5 会话管理

需要支持：

- 创建会话。
- 获取会话列表。
- 删除会话。
- 加载会话消息。
- 按最近更新时间排序。
- 展示会话标题、最近更新时间、最后一条摘要。

首版标题策略可采用：

- 会话创建后默认先显示“新对话”。
- 当用户发送首条消息后，客户端使用首次用户输入内容生成标题。
- 标题生成规则建议为：截取首条用户消息前 20 到 30 个可见字符，去除多余空白与换行。
- 若后端后续支持自动摘要标题，可再评估是否切换为服务端生成。

### 7.6 项目管理

项目模块用于承载“当前在哪个项目上下文中聊天”的概念，首版要求：

- 支持本地维护项目列表。
- 每个项目至少包含名称、根目录、默认 agent、默认模型、描述。
- 支持设置当前活动项目。
- 聊天输入区显示当前项目。
- 会话可以绑定所属项目。

首版项目数据可以先存本地 TOML，不强依赖网关。

### 7.7 网关接入

客户端必须对接现有网关服务，首版最少覆盖以下接口能力：

- `POST /v1/conversations`
- `GET /v1/conversations`
- `GET /v1/conversations/:id/messages`
- `POST /v1/conversations/:id/messages`
- `DELETE /v1/conversations/:id`
- `GET /v1/ws/chat`

如需 agent 选择或实例信息展示，可扩展：

- `GET /v1/agents`
- `POST /v1/agents`
- `GET /v1/agent-instances`

接入要求：

- 统一封装前端 API Client。
- 流式响应对桌面端使用 WebSocket。
- 统一错误码映射为前端可读消息。
- 支持请求超时、主动取消和网络中断处理。

WebSocket 首版建议职责：

- 客户端建立单条会话级或应用级 WebSocket 连接到 Gateway。
- 客户端通过 WebSocket 发送消息请求、取消请求和心跳。
- Gateway 通过 WebSocket 推送增量内容、完成事件、错误事件和连接状态事件。
- `gateway -> claw` 内部第一阶段允许继续使用现有 SSE / channel 转发，优先改造 Gateway 对桌面端的外部协议。

### 7.8 搜索模块

搜索模块首版定位为全局入口，范围从轻实现开始：

- 支持搜索会话标题。
- 支持搜索项目名称。
- 支持搜索本地设置项或快捷入口。

若网关后续补充搜索 API，可扩展为消息全文搜索。

### 7.9 技能模块

技能模块首版至少具备：

- 技能列表页。
- 技能基础信息展示：名称、说明、来源、启用状态。
- 技能详情抽屉或详情页。

若网关暂无技能接口，首版可使用本地配置或占位数据驱动界面结构。

### 7.10 插件模块

插件模块首版目标是预留产品结构：

- 插件列表。
- 插件状态展示。
- 插件详情页。
- 插件启用/禁用开关的 UI 位置。

若当前后端没有对应 API，首版允许只做只读结构。

### 7.11 自动化模块

自动化模块首版目标：

- 展示自动化任务列表。
- 展示任务名称、类型、状态、计划时间。
- 提供“创建自动化”入口占位。

该模块首版可不接真实执行能力，但页面结构需要提前保留。

### 7.12 设置模块

设置页必须支持：

- 网关基础地址配置。
- 请求超时配置。
- 默认模型配置。
- 默认 agent 配置。
- 默认工作目录配置。
- 主题配置。
- 日志级别配置。
- 应用版本与运行信息展示。
- 配置保存、重置、测试连接。

## 8. 配置管理需求

采用 TOML 作为本地配置格式，建议分为以下结构：

- 应用基础配置。
- 网关连接配置。
- UI 配置。
- 默认会话配置。
- 项目列表配置。

要求：

- 应用启动时自动读取。
- 设置保存后自动写回。
- 配置错误时给出明确提示。
- 保留默认配置生成能力。

建议示例结构：

```toml
[app]
theme = "light"
language = "zh-CN"

[gateway]
base_url = "http://127.0.0.1:8080"
timeout_ms = 60000

[chat]
default_model = "local bridge"
default_agent_id = ""

[[projects]]
id = "icoo_claw"
name = "icoo_claw"
root = "E:/code/issueye/icoo_claw"
```

## 9. 前端架构要求

### 9.1 技术选型

- `Vite` 负责前端构建。
- `Vue3` 负责组件与页面开发。
- `Pinia` 负责状态管理。
- `Vue Router` 负责主视图路由。
- `Tailwind CSS` 负责样式体系。
- JavaScript 作为前端开发语言，首版不强制 TypeScript。

### 9.2 前端模块划分

建议至少拆分为：

- `layout`：应用框架、侧边栏、标题栏、内容容器。
- `views`：快速对话、搜索、技能、插件、自动化、设置。
- `components/chat`：消息列表、输入框、流式块、状态条。
- `components/project`：项目列表、项目切换器。
- `stores`：app、settings、projects、conversations、chat、agents。
- `services`：gateway API、wails bridge、config adapter。

### 9.3 状态管理要求

- 全局保存当前项目、当前会话、连接状态、主题、配置摘要。
- 会话消息缓存与会话列表缓存分离。
- 流式响应状态与历史消息状态分离。
- 明确 loading、empty、error 三类基础状态。

## 10. Go/Wails 桥接要求

Wails3 的 Go 层主要负责：

- 应用生命周期管理。
- 本地 TOML 读写。
- 打开目录选择器。
- 获取系统路径和用户目录。
- 读取应用版本、运行环境、日志目录。
- 后续扩展系统托盘、通知、文件打开能力。

前后端边界要求：

- 网关业务请求优先由前端直接调用 HTTP / WebSocket。
- 本地系统能力通过 Wails3 Go 方法暴露给前端。
- 禁止将 UI 状态逻辑堆入 Go 层。

## 11. 非功能需求

### 11.1 性能

- 应用首屏可交互时间应尽量控制在 3 秒内。
- 会话列表切换应为即时反馈。
- 流式渲染过程中不得明显卡顿。

### 11.2 可用性

- 网络错误、超时、会话忙碌等错误必须可读。
- 不能因为单次请求失败导致整个界面不可继续操作。
- 应支持恢复到欢迎页和重新发起新会话。
- WebSocket 断连后应提示重连状态，并支持手动重试或自动重连。

### 11.3 可维护性

- 前端按模块拆分。
- 配置结构稳定，可演进。
- 网关 API 访问统一封装。
- 保留后续从 JavaScript 迁移 TypeScript 的空间。

### 11.4 可扩展性

- 左侧导航模块允许后续增加更多工作台页面。
- 会话消息结构需兼容后续工具调用事件、图片、附件和系统消息。
- 设置项需支持后续增加鉴权字段和多网关配置。

## 12. 页面与路由建议

建议路由：

- `/chat`
- `/chat/:conversationId`
- `/search`
- `/skills`
- `/plugins`
- `/automations`
- `/settings`

项目列表和对话列表建议作为左侧持久面板，不单独占完整页面。

## 13. 数据模型建议

客户端本地至少维护以下核心模型：

- `AppSettings`
- `GatewayConfig`
- `Project`
- `ConversationSummary`
- `ChatMessage`
- `AgentProfile`
- `PluginSummary`
- `SkillSummary`
- `AutomationSummary`

## 14. 分期规划

### P0：聊天 MVP

- Wails3 技术验证通过。
- Wails3 应用壳。
- 左侧导航基础布局。
- 设置页和 TOML 配置。
- 网关连接测试。
- 会话列表。
- 创建会话。
- 消息发送与 WebSocket 流式展示。
- 历史消息加载。
- 搜索、技能、插件、自动化占位页。

### P1：工作台增强

- 项目管理。
- 搜索模块。
- 模型/agent 切换。
- 更完整的错误处理。
- 会话删除、重命名、固定。

### P2：能力扩展

- 技能/插件/自动化真实接入。
- 文件上下文。
- 多网关配置。
- 快捷键体系。
- 系统托盘与通知。

## 15. 验收标准

- 应用可在 Windows 桌面正常启动。
- Wails3 热重载、Go/JS 绑定、目录选择器和 Windows 构建链路验证通过。
- 用户可在设置页保存 TOML 配置并通过连接检测。
- 用户可创建会话并完成至少一轮基于 WebSocket 的流式问答。
- 用户可查看历史会话并重新进入继续对话。
- 网络异常和接口异常有可见反馈。
- 关闭并重新打开应用后，本地配置仍然存在。

## 16. 当前待确认事项

- 技能、插件、自动化数据首版是否允许使用本地静态配置占位。
- 是否需要在首版纳入多模型切换和 agent profile 管理。

## 17. 结论

该桌面客户端的正确切入点不是一次性做全量 Codex App，而是先围绕现有 `gateway` 的 conversation 能力完成桌面聊天 MVP，再把搜索、技能、插件、自动化作为可扩展工作台逐步补齐。这样能最大化复用当前仓库后端成果，并把 Wails3 + Vue3 的客户端工程边界控制在可交付范围内。
